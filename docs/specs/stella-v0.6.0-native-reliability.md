## 目标与边界

让已有 Pi 原生聊天的每一次输入、事件、历史消息和文件反馈都有可追踪的身份与明确结果。修复已复现的 UTF-8 分块损坏和同时间戳消息覆盖，并补齐真实故障恢复路径。保留现有模型、Skills、独立会话、文件预览、皮肤和 Team 能力。

- 不修改或 fork 官方 Pi，不升级到未经验证的新 Pi 版本，不读取 API Key 作为诊断内容。
- 不移植 Orca 的 PTY、SQLite journal、SSH、Relay、通用 Agent IDE；不改 Team 状态所有权。
- 不添加自动重发、伪造成功、静默丢事件/历史或“超时即未发送”的行为。
- 本轮是本机实现、检查、构建与 Windows 安装包升级；不推送、提交 PR 或发布云端版本。

## 业务不变量

### 1. RPC 数据完整性与运行代际

每个进程独立拥有 UTF-8 decoder、stdout 残片、stderr、pending requests、generation 和事件序号。任意字节切分、CRLF、末行无换行均不得改变有效内容。损坏/截断协议必须明确报错。旧进程退出、迟到的 stdout/stderr/error/timeout 不得污染新进程或拒绝新请求。

桥接信封包含 runtime generation、session scope 与单调 sequence；payload 保持 Pi 原生事件。导航期间的旧 scope 不得更新新会话。快照须来自同一运行代际与会话，不能混合多个并发导航结果。

### 2. 消息身份

`timestamp`、角色和正文都不是唯一键。实时 `message_start` 创建一次独立出现，update/end 只更新相应的当前生命周期。历史消息使用官方 Session entry ID，并按当前分支投影；同角色、同毫秒甚至正文相同的两次独立消息必须保留。分支按钮必须关联准确 entry。流式更新不重新解析未变的历史正文。

### 3. 原生提交回执与恢复

GUI 为一次提交创建稳定 submission ID，Main 在调用 Pi 前原子落盘。状态为 `pending` / `accepted` / `rejected` / `unknown`，不混淆“Pi 接收命令”和“模型成功完成任务”。同 ID 同内容重复 IPC 不得再次执行；同 ID 不同内容明确拒绝。

崩溃、断连、写入回执失败后的不确定状态必须保留并显示。重启将遗留 pending 标为 unknown，不自动重放。用户可以查看回执、复制追踪信息并核对会话；草稿只在明确接收后按原有 revision-safe 规则确认清理。正文/附件不复制进诊断包。sidecar 不成为 Pi 历史的第二事实源。

明确拒绝后，用户再次点击发送是一次新的提交；丢失 IPC 响应但没有可观察结果时保持原 ID。Pi 子进程中断后的重连保持当前 Session 身份和草稿，不隐式重发旧输入；断连诊断保留中断会话关联并明确标记未连接。

### 4. 本机诊断

检查器提供显式导出入口：版本、运行代际、session/request 关联 ID、事件类型与序号、提交状态、UI 布局和协议健康。默认不导出完整提示词、回复、文件内容、密钥、环境变量或原始 stderr。无后台上传。用户明确选择的导出目录由系统对话框处理，失败可见。

### 5. 顺序一致性与性能

同批事件按接收顺序完整折叠，发布一次；结束刷新在批状态提交后触发。证明批处理与逐事件处理语义相同。以实际渲染/Markdown 解析工作量及多消息负载做回归，不用丢弃数据换吞吐量。本轮不无依据地新增虚拟列表依赖；已有阅读锚点必须稳定。

### 6. 会话查看状态

完成/失败/待用户输入与未读属于原生会话呈现状态，不写 Team/Board 状态。持久化 GUI 阅读位置、已读标记和文件选择等视图元数据；使用版本化 sidecar/视图存储，遇到未来 schema 明确拒绝写入，不能重置用户数据。回到会话恢复阅读位置，不抢滚动。

### 7. 文件反馈闭环

现有右侧预览支持把当前文件/可选选区引用到输入框。引用包含路径、文件版本及用户实际选择的文本，不把整个文件暗中塞入上下文。区分“消息提及文件”和“本机读取验证成功”；版本变化要求显式刷新。HTML 继续隔离脚本和外部资源，Office 继续内容与样式预览，不接 Office 插件。引用不得覆盖用户已有草稿或发送过程中新增内容。

## 验收

必须通过专门回归、项目 `npm run check`、生产构建和真实 Electron + 官方 Pi 的原生 E2E。受控 RPC/模型夹具只能验证交互与协议，明确标注，不宣称真实云模型成功。安装包检查版本、资源内容、启动和关键原生路径；没有 macOS 环境时不宣称完成 macOS 安装验证。

故障验收包括：逐字节中文/emoji、无末行换行、截断 JSON、旧进程退出晚于新进程启动、同毫秒重复消息、刷新与消息并发、提交响应丢失/重启、重复 IPC、不匹配 schema、诊断不含敏感内容、不同文件切换/引用、批处理顺序等价和历史解析不随新 token 增长。
