# Sol 模式：单官方 Pi 的可选优化扩展

日期：2026-09-19。需求：把此前只研究的 NVIDIA SoL-Pi 实际接入，并提供可验证的开关，不维护第二套 Pi 核心。

## 范围与归属

- 官方 Pi 0.85.1 继续拥有模型、凭据、工具、会话、Agent loop 和原生压缩；不修改它的源码或安装第二份运行时。
- 固定 NVIDIA SoL-Pi `bd005888b9b8a3fcdb511feb91fc27d3dfa8f2b1`（0.1.0，MIT）源码，保留许可证及可审查的适配记录。用独立构建入口生成扩展，仅由现有原生聊天 Pi 进程加载；Team/托管任务不自动注入。
- Stella 负责配置、空闲切换、实际加载确认、错误与用量展示；不会覆盖用户全局或项目 `sol-pi.json`，也不会关闭用户其他扩展。

## 用户路径

偏好设置 → Sol 模式。默认关闭；总开关开启后可分别选择 Action Fusion、ObservationPack、辅助模型提炼（EPR）、阶段压缩（OCC）。初始基础配置为前两项开启，后两项关闭。

EPR 明示会把符合条件的诊断日志发送给所选辅助模型、产生额外费用；只能选择现有 Pi 模型目录里的模型，不创建独立凭据。OCC 明示可能在阶段边界调用原生压缩并自动继续，策略比例不是已验证的节省金额。高级配置按需展开。

点击应用时只在原生运行空闲、没有压缩或排队时保存并重载。运行中显示等待原因，不中断任务、不静默延后应用。保留当前 Session ID、消息、模型、思考级别、草稿、附件与阅读位置。启用/关闭均需实际加载结果，不能仅凭配置文件写入显示成功。加载失败保留明确错误与可关闭恢复的入口。

## 接入与适配

1. 主进程验证完整配置，经已有原生维护互斥窗口应用，以子进程专属启动配置传给扩展；不用全局环境变量或用户 Pi 配置文件改写模式。
2. 扩展通过公开 Extension API 注册工具与事件；加载回执携带本次启动标识。主进程区分配置、当前生效、失败/未加载，运行代际不匹配的回执不更新状态。
3. Action Fusion 检查 bash 是否可用，并在任何文件修改前确认组合命令；写入与后续命令各自呈现结果。它是 edit/write 事件，不会额外触发第三方仅针对 bash 的钩子，这一点在确认框明示；要求该类策略拦截的环境应关闭 Fusion。后续命令失败不能抹掉已经完成的写入，也不能标成整体成功。
4. ObservationPack 保留原 JSONL，归档原文并提供分页召回；分支/会话切换重建发送计数。Windows 与 POSIX 均校验规范路径、目录链接、文件类型及打开句柄身份，拒绝归档重定向、替换、损坏。
5. EPR 使用同一 Pi 模型目录与认证；保留上游证据核验，失败不丢原结果。每次未应用及原因可见，不用绿色标记伪装优化；辅助模型用量单列，无法获知费用时明确显示未知。归档文件必须随会话备份，不宣称摘要完整或医学结论正确。
6. OCC 使用实际 Pi 的 retained-tail 参数与合法压缩边界；取消/压缩失败不续跑，压缩中的会话切换不改变活动分支。阶段计划不是看板任务验收，不能自动把任务标记完成。
7. 与已加载的同名扩展工具冲突时明确报错，不静默重复注册；不声称能识别任意仅注册事件钩子的优化器，不能同时安装另一份 SoL-Pi。模式关闭只移除本适配器；第三方扩展自身行为不被本开关伪装为关闭。

上游日志优化的阈值、分页与原文保留语义属于所选机制本身，不引入任务回合上限。文件读取拒绝不可信链接是本次接入必需的安全约束，错误明确可见；关闭相关优化即可恢复 Pi 原生路径。

## 验收

- 配置校验、持久化、加载确认、错误恢复、运行中拒绝切换、旧回执隔离。
- 实际 Pi RPC 启用/关闭、同一 Session/模型/草稿保留，四项机制注册及对应行为。
- 真实写文件+命令成功/失败/取消，未授权命令不执行；后台进程监管仍有效。
- 大文本原文归档、投影、分页召回、分支恢复；坏归档与 Windows junction 负向测试。
- EPR 真正走辅助模型协议、统计用量；坏证据/模型失败显示未应用，保留原始结果。
- OCC 原生压缩后续跑、连续阶段、停止不复活，且原生自动压缩仍正常。
- 设置页键盘操作、窄窗口、实际状态可读；生产构建与 Windows 打包态验证。同一依赖树只有一份官方 Pi。
- 本地协议夹具必须标记为测试，不冒充真实模型效果；远端实测单列，不承诺固定节省比例。macOS 未运行的部分如实列出。
