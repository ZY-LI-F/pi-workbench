# Pi 原生可靠性、文档预览与版本同步

本批实现维护现有 Pi GUI，不接入第二套 Pi，不改变官方 Pi 核心源码，不新增 Team 工作流。源码 Pi 目标版本直接读取随 GUI 发布的 `VERSION`，GUI 自身版本号不是 Pi 的版本号。

## 长会话与统计

- 完整状态只读取官方 `get_entries`，不再请求递归 `get_tree` 后将其直接送入 Electron contextBridge。
- 图谱投影保留每个节点的 entry、父 ID、子 ID、时间顺序及标签变更；孤儿按原 Pi 规则显示为根。不截断历史，不减少深层节点以规避传输错误。
- `message_end`、`compaction_end`、`agent_settled` 请求独立 `get_session_stats`。200 ms 合并同批事件、单请求串行排空；并非压缩阈值或运行上限。
- 数值来自 Pi，不用历史累计 tokens 冒充活动上下文。不替换流式消息，不改写运行标志；会话 ID、运行代际及序号防止迟到统计覆盖新会话。失败显示最后成功数值及明确错误。
- 点击当前会话只切回聊天视图；不会再次加载相同会话、打断运行或清空草稿。

## 后台计算生命周期

独立启动适配器在官方 RPC 入口执行前等待主进程完成监管握手。核心依然是原来的公开 Pi RPC 入口；没有替换工具或修改 Pi 包。

- Windows：将每个 Pi 进程加入独立 Job Object。子进程自动属于同一 Job，启动 shell 退出或 `nohup` 继续执行不会丢失归属。停止时只终止经 Job 成员校验的子进程，保留 Pi 本身和其他应用；PID 被重用时不能凭旧 PID 杀进程。Job 句柄关闭会清理该运行实例。
- POSIX：为每个 Pi 运行实例生成随机环境标记，后代默认继承；停止前再次核查标记，处理 `nohup` 重定父进程的情形。进程枚举的环境数据仅留在主进程内存中，不进入 GUI、日志或诊断导出。
- `abort` / `abort_bash` 同时中止 Pi 与受管子进程，等待两者结果后报告。清理期间新提交等待，不能启动后再被上一轮停止误杀。清理失败明确报错，不报告“全部结束”。10 秒核验期满仍有进程会报错，而不是假装成功；不限制正常任务运行时间。
- 回合中使用输入区停止按钮；Pi 空闲但有后台工作时，使用检查器活动页的停止入口。
- 不把本机停止扩张为 SSH、容器、外部守护进程或主动清除继承环境标记的任务取消。此边界出现在按钮提示与停止回执中。
- 原有测试/运行实例中的后台进程不会被事后接管；需新版本启动的 Pi 实例才具有监管范围。

Microsoft 的 [Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)说明了子进程归属、Job 关闭及嵌套 Job 行为。这里按独立运行实例管理，不使用按进程名杀进程的方式。

## PPTX 与 PDF

- PPTX 沿用现有本地解析器，保持演示稿原始宽高，不把所有文稿硬编码成 960×540。ResizeObserver 按可用宽高计算适应整页；放大后画布滚动，工具栏不缩小。
- 原生尺寸的幻灯片建立独立层叠上下文，避免转换器的负层级背景被白色画布遮挡，保留深色背景上的浅色标题。
- 页码下拉、前后翻页、预览区域快捷键、手动缩放和重新适应可并用。更换文件重新初始化；已关闭/切换的解析请求不会覆盖新文件。
- 幻灯片仍在空 sandbox iframe 内，CSP 禁止脚本、网络、表单与外部对象。复杂排版不承诺与 PowerPoint 像素级一致。
- PDF 改用 PDF.js，本地 Worker + CMaps + 标准字体 + 解码器都进入构建产物，不依赖 Chromium 辅助文本服务或外部 CDN。支持连续页滚动、页码导航、适应宽度和倍率。
- 只为可见及邻近页面分配画布/文字层；缩放、文件切换、关闭时取消渲染并释放画布和文档。文本在文字层可选、可复制，扫描页没有文字时明确说明不含 OCR。
- 不调用 PDF JavaScript/表单执行接口。文字提取或渲染失败在对应页显示，不把图像可见当作文本提取通过。
- PDF.js 作为构建依赖，避免把仅供 Node 使用的可选 canvas 原生包塞入桌面安装包。运行所需浏览器代码及离线资源已由 Vite 输出。

PDF.js 的 [示例](https://mozilla.github.io/pdf.js/examples/)与 [API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)是本地页面、字体、Worker 和文字层的实现依据。

## 本机 Pi 版本

- 启动时只读检测；不访问 registry 查询 latest，不自动安装。偏好设置显示 GUI 版本、GUI 内置 Pi、实际本机 Pi 启动位置与可更新的全局目录。
- 排除应用自身 `node_modules/.bin`，避免开发启动的 PATH 把内置依赖误判成本机全局安装。
- 解析 Windows npm/Pi shim 到 Node 入口，以参数数组调用，不执行拼接 shell。匹配包名、bin 声明、npm prefix/root 与实际 Pi 包路径后才允许同步。
- 确認窗口提供实际旧版本、目标版本、目录、降级可能与权限/联网说明，默认取消。取消不调用 npm install；同一时刻只有一个安装请求。
- 确认后再次核对目标身份，使用 `npm install --global --prefix <已确认目录> @earendil-works/pi-coding-agent@<GUI内置版本>`，不使用 latest、force 或自动提权。具体版本安装是 [npm install](https://docs.npmjs.com/cli/v11/commands/npm-install/) 的标准行为。
- 安装后同时验证实际包版本与 `pi --version`；失败、权限问题和安装位置不匹配都明确展示，不制造成功。
- 找不到全局 Pi 时不强迫安装，GUI 内置核心照常可用。旧命名空间、自定义二进制或不能确认归属的包装脚本应通过原安装工具管理。
- Sol-Pi 当前仅完成可行性研究，本批不安装扩展，也不出现虚假的可启用开关。

## 验收

运行版本检测/取消、真实 Office/PDF 解析、超过 contextBridge 旧递归限制的长会话、长回合统计刷新以及真实后台进程退出测试。以本次实际记录为准；Windows 验收不能代替 macOS 实机测试。未要求发布时，不自动自增版本、推送、打 Tag 或产出安装包。
