# Team / Kanban 长任务实测问题修复

## 范围与证据

依据 2026-09-19 安装版 v0.7.3 的 Computer Use 长任务实测，修复渲染和页面导航，不改 Pi 核心、不改任务调度协议、不迁移 Board 数据。本次测试里的合计数值错误来自模型生成的业务文件，已由原任务返工处理，不通过 GUI 硬编码答案。

## 改动

1. 执行图：每个 Leader 验收节点拥有独立的“合并图标 + 节点”行；同轮多次验收不再落进 20px 图标列。
2. 执行事实：卡片分开显示根执行负责人和当前正在运行的执行树节点；排队/等人/等成员不冒充执行中；忽略历史执行、其他任务和终态节点，支持多个运行成员及嵌套委派。旧 Workflow 不覆盖当前 AgentTask 的状态和成员。
3. 卡片布局：负责人、事件/状态分行；顶端标签可换行；长名称和工具事件省略并保留悬停全文，不减小字体来掩盖挤压。
4. 频道导航：选择由应用壳层持有，按规范化项目路径独立保存。页面卸载不丢选择，项目切换不串频道，加载中不清空，任务实际删除后回到启动台。显式“新建团队任务”仍进入启动台；历史的新建请求不会在返回页面时再次清空选择。
5. 拖动：旧代码已在隔离 Electron 中从标题、正文成功拖动并持久化阶段，原 Computer Use 失败未复现。不无依据更换拖拽机制；加入回归用例。

## 验证方式

- 纯函数/组件测试：当前执行者过滤、多成员/嵌套树、历史 Workflow、同轮多个验收节点、页面卸载、项目切换、加载与删除。
- Electron 回归：独立 auth/session/user-data/project；本地协议 fixture 明确属于测试基础设施，不是真实模型。业务拖拽、页面导航、Board 保存和布局由真实应用完成。
- 增加真实 Pi 协议链路回归：本地确定性 Provider 提交 Coordinator 委派、暂停 Worker 的响应以检查实时卡片，再释放响应，确认回到同一频道并由人工接受才进入完成。它验证应用集成，不替代真实模型长任务质量评估。
- 扩展项目看板回归发现既有测试竞态：`selectOption` 返回后立即读取 Board，可能抢在异步提交前读到 planned。失败产物中任务与活动已正确持久化为 review；修正测试为等待界面显示提交结果后再读 Board，不增加固定休眠，不改业务保存逻辑。
