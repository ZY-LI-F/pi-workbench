## 项目管理与任务闭环

[项目 E2E](../../tests/e2e/project-board.spec.ts) 使用真实 Electron、preload、Main IPC、BoardStore 和项目文件。临时目录选择通过明确的系统对话框测试替身返回；项目校验、落盘和任务更新均执行真实实现。

第一项场景验证：

1. 从当前目录和历史 Task 发现项目，创建一个没有 Task 的新项目，编辑名称、说明并置顶。
2. 菜单修改项目阶段，真实拖动卡片到“暂缓”列；将另一个项目设为“已收尾”，仍显示其尚未验收的手工任务，Task 保持 review。
3. 搜索能命中 Task 内容。查看项目、修改元数据和下钻任务期间，当前 Pi 的 Session ID 与 cwd 保持不变。
4. 非当前项目 Task 以只读方式打开，新建入口不能把任务写到错误项目；显式打开实际工作区后，使用原 Task 详情手工完成任务。
5. 归档、筛选归档项目、恢复项目；任务完成比例和阶段如实更新。
6. 重启后项目 ID、名称、置顶和计划阶段保留；没有页面脚本异常。

第二项场景向真实项目文件写入未来版本 `99`，验证项目页显示具体错误、重新读取仍报告错误、原文件字节不变，同时独立 Pi 仍可使用。其他损坏、写入失败、目录缺失和路径变化场景由真实临时文件单测覆盖。

## 不选择项目与长列表

第三项场景以 `recentProjects: []` 且没有 `lastProject` 的真实首次启动状态进入应用。预置 120 个 Task：60 个已归属项目，60 个未归属；只在测试准备阶段用一次 BoardStore 事务生成数据，不向产品加入示例列表或条数上限。

- 任务看板默认“不限项目”，显示全部 120 项；未选择工作区时通过 `Ctrl+N` 新建任务，表单默认“不选择项目”。
- 新 Task 没有 `projectPath`，`trusted` 为 false。可保存评论和手工移到待审核；项目清单不生成虚构的“未归属项目”目录。
- 切换到未归属任务，验证待规划列的内容高度大于可用高度，鼠标滚轮产生实际滚动；打开最后一张卡片，详情对应其原 Task。
- 项目详情包含全部 60 个所属 Task，其列表拥有自己的滚动区域，最末项可以到达。
- 打开真实工作区后，将任务绑定到该项目；保留 Task ID 和 review 阶段，再手工完成。关闭并重启应用后，另外 60 个未归属 Task 仍未绑定，新 Task 保留完成状态和真实项目路径。
- 将窗口设置为 720 × 800，任务看板可以在自身内部横向滚动；右侧列可到达，“新建任务”按钮高度与位置仍在窗口内。

最终补充的同一场景还直接提交一个与当前工作区不同的预期路径，已验证 Main 拒绝且任务保持未归属，然后经可见的“绑定到 project”按钮正常绑定。切换到“未归属项目”筛选时，已经绑定的 Task 详情正确关闭，展示范围与详情一致。

[未归属任务单测](../../tests/unit/unassigned-task.test.ts) 另验证编辑、删除、评论不触发 Skills/Agent 分发、绑定后的身份和历史保留、拒绝二次绑定、未绑定时拒绝自动执行，以及持久层拒绝附带执行或会话来源的无项目任务。[任务编辑器测试](../../tests/unit/task-project-editor.test.tsx) 覆盖已有工作区和没有工作区两种“不选择项目”创建入口。

## 存储与故障验证

项目元数据单独保存在 `userData/projects.json`，schema 为 1。真实任务继续保存在原 `userData/board/board.json`，项目进度由这唯一一份任务与当前执行状态派生。

- [项目清单测试](../../tests/unit/project-registry.test.ts) 验证超过 12 个项目的长期保存、重启、重复目录与归档、增量发现、并发字段更新、空操作不重写、写入失败后保留旧提交、坏文件和未来版本不覆盖，以及目录不可用的显式状态。
- [路径与项目投影测试](../../tests/unit/project-board.test.ts) 验证 Windows / UNC 的一致标识与 POSIX 大小写区分，按 Task 而非执行尝试计数，当前执行与历史注意事项分开，空任务、不可用数据、筛选和排序。
- [Renderer 状态测试](../../tests/unit/use-project-registry.test.tsx) 验证晚到的旧读取不能覆盖新保存，以及刷新失败保留最后有效快照并显示错误。
- [项目 UI 测试](../../tests/unit/project-board-ui.test.tsx) 验证编辑与阶段操作、失败时表单保留、导航与只读边界。
- Board schema 从 v9 升级到 v10。真实文件测试先写入 v9 数据，验证迁移前产生 `board.json.v9.<时间>.<ID>.bak`，备份与旧文件内容完全一致，任务保持原 ID、项目路径与规格。缺失项目路径的坏 v9 记录被拒绝，不被解释成合法未归属任务。

v10 新增的可选路径是明确的数据格式变化。旧版应用不能读取新格式；本次验证的是向前迁移及原始备份保存，没有实现旧格式导出或自动降级。没有修改生产用户的 Board、项目目录或 Pi 配置来执行这些验收。

Companion 的共享 Task 摘要允许省略路径，项目目录汇总跳过未归属 Task。其 Web 构建和单测已通过；本次未执行 Android 模拟器、原生 APK 或真机验收。

## 覆盖边界

本次完成 Windows 源码构建和真实桌面操作验证，没有生成或发布新版安装包，没有执行 macOS/Linux GUI、Android 原生或全部仓库 E2E。研究结论来自固定提交的上游源码和官方文档，未运行上游系统及其测试；固定提交不是对最新版本的声明。

设计取舍均可结合已有任务、执行与验收规则直接确定，目前没有必须由用户裁决的矛盾，因此没有创建 `【问题确认】` issue。
