### Sol 专项行为

- 页面启用/关闭：必须收到当前启动的加载回执，保留 Session ID、消息、模型和草稿；窄窗口无横向溢出，可用 Space/Enter 操作。
- 重复工具冲突明确失败；关闭模式恢复原先未持久化的空会话，不创建替代会话冒充恢复。
- Fusion 取消发生在写入前；真实文件修改和组合命令成功/非零退出均核验；后续命令失败不撤销或隐瞒已发生的写入。
- ObservationPack：前两次完整发送，随后真实投影，`obs_recall` 返回原文，JSONL 保留原证据；分支恢复重置发送计数。
- EPR：经 Pi 模型/凭据接口发起真实 HTTP 协议调用；原文引文验证通过才应用，编造引文时保留原结果并显示原因；用量只计一次，重载后按当前分支恢复。
- OCC：依据 Pi 合法压缩前缀调用原生压缩并续跑；取消中途压缩后不重新发起任务，仍可手动发送下一轮。测试也断言扩展实际收到主进程的停止通知。
- Windows junction、硬链接、损坏归档、写配置失败、过期加载回执和输入校验均有负向单元用例。

## 验收发现与修复

1. Windows 归档创建路径误尝试 `mkdir` 盘符根目录：只验证根，逐级创建其下目录，并校验规范路径与文件句柄。
2. 阶段压缩若按“总量减尾部”估算，会误判包含工具调用的不可切断消息组；改为 Pi 的合法 cut point。单次 split-turn 压缩可能产生两次摘要模型请求，测试按压缩记录/续跑次数而非请求数判断。
3. 启动握手后断开的 IPC 不能传达 Sol 取消意图；仅 Sol 启用时保留非保活 IPC，增加实际接收断言。
4. 崩溃进程与状态刷新竞态触发 stdin `EPIPE`，旧逻辑只处理 write 回调，没有处理流的 `error`；已显式处理并停止失效运行。被信号结束的子进程不再等待一个已经发生的 exit。单元与真实 Electron 断连/重连检查保留会话和草稿，不重放任务。
5. 正在入队或执行 bash 的配置申请必须立即拒绝，而不是等任务结束后应用过时选择；维护窗口同时保护异步申请间隙。
6. 旧版本页面测试仍要求“Sol-Pi 尚未接入”；改为断言真实开关默认关闭，保留 Pi 版本核对和取消更新验证。
7. 全新安装、未选模型时，Pi 返回 `unknown/unknown`、`api: unknown`、窗口为 0 的精确占位对象；不能将其作为真实 provider 传给重启命令。统一模型身份转换显式识别该原生“尚未选择”状态，仍严格校验其他模型身份，不替用户选模型。

测试修正单列：新增安装态切换最初直接调用 IPC，绕过界面应用后的刷新，随后拿旧渲染层地址做复制断言；改为真实设置按钮路径。打开设置会按现有设计收起侧栏，旧冒烟固定要求窄布局的“更多”，因此在继续原有窄布局检查前显式重新展开侧栏。这两项是测试前置状态修正，没有修改生产 UI 或放宽复制/启动断言。

## 复现命令

```powershell
npm run check
npm run build
npm run test:e2e:native -- --output test-results/native-sol-final

npx electron-builder --config electron-builder.config.mjs --win nsis --x64 --publish never --config.directories.output=release/v0.7.3
$env:STELLA_PACKAGED_EXECUTABLE = "$PWD\release\v0.7.3\win-unpacked\Stella Pi Workbench.exe"
npx playwright test tests/e2e/packaged.spec.ts tests/e2e/sol-mode.spec.ts tests/e2e/native-reliability.spec.ts --output test-results/sol-packaged-final

# 真实模型测试会产生费用；明确选择本机已配置的 provider/model。
$env:STELLA_SOL_LIVE = '1'
$env:STELLA_SOL_LIVE_PROVIDER = 'deepseek'
$env:STELLA_SOL_LIVE_MODEL = 'deepseek-v4-flash'
npx playwright test --config playwright.live.config.ts tests/e2e/sol-mode.live.ts --output test-results/sol-live-acceptance
```

普通 E2E 使用明确标注的本地模型协议夹具，但 Electron、官方 Pi、IPC、文件工具与文件系统均真实运行。不能把它们算作真实模型效果验证。Live 用例使用隔离副本，结束后删除该用例的 auth/models 副本，不触碰用户原配置。
