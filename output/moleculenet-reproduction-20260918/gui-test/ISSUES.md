# 本次真实长任务中的 GUI 问题

本记录属于测试产物，没有修改 PI-GUI 业务代码。环境：Windows、Electron、隔离用户配置、Pi 0.85.1、DeepSeek V4.1 Flash。截图见同目录 evidence。

## 1. 长任务统计未随完成的模型响应刷新

运行期间消息持续追加，但检查器仍显示 0.059M 活动上下文、1.09M 累计缓存读取，左侧任务消息数仍为74。发送运行中补充指令后，面板刷新为0.079M、5.85M、211条消息。这不是把累计用量误当上下文，也不证明自动压缩失败。

源码依据：`src/renderer/src/components/Inspector.tsx:131` 读取 `bootstrap.stats`。`src/renderer/src/hooks/use-pi-runtime.ts:92` 在 `agent_settled` 后安排完整刷新，未在同一长回合每次完成的响应后更新这组统计。`src/main/index.ts:984` 的 bootstrap 路径才请求 `get_session_stats`。

影响：用户无法从该面板判断长任务的实时消耗和活动上下文。建议的修复边界是让统计更新与消息流解耦，并保持原生 Pi 的上下文估算口径，不自行计算一个含义不同的替代值。

## 2. 特定中栏宽度下顶部控件重叠

左栏收起、中栏约1120px时，会话快捷按钮与长项目名发生重叠。中栏约650px时会切入“更多”，隐藏功能仍可访问。截图03和04记录两种状态。

源码依据：`src/renderer/src/styles/app.css:1220` 的 session track 与其按钮可缩到 `min-width:0`，但按钮文字保持 `white-space:nowrap`；项目面包屑在 `workspace-pane <=1080px` 才隐藏，其他操作在900px才进入更多。该区间的实际可用宽度还受右侧控件及标题栏留白影响。此为与实测一致的静态原因分析，尚未用布局测量工具确定每个元素的溢出量。

## 3. 配置页点击已选中的任务不能回到聊天

从模型配置页面点击左侧当前任务，没有回到会话。通过“PI原生工作台 → 当前会话”可以返回。

源码依据：`src/renderer/src/App.tsx:460` 的 `switchSession` 在路径与当前 session 相同时立即返回，早于后面的 `setWorkspaceView("chat")`。因此“切换会话无须重新加载”和“显示当前会话视图”被合并成了同一个条件。

## 4. 停止 Pi 等待不等于终止 detached 后台训练

Pi 为长训练使用 nohup。点击停止后当前等待工具结束，已 detached 的 Python 子进程继续执行。主代理随后核对完整命令行，仅停止错误单位批次的两个已确认 PID，保留失败证据。

这是进程生命周期边界，不应宣传为全部计算均已停止。此次没有扩展业务代码实现后台作业注册、进程树跟踪或取消协议。

## 5. 文件列表依赖助手正文中的路径

Pi 的 `write` 工具已返回阶段报告写入成功，右侧列表仍显示0项。`src/renderer/src/lib/session-files.ts:24` 只扫描 assistant 消息中的 text block，不扫描写文件工具的输入或成功回执。此次须让 Pi 在助手正文再次给出绝对路径才能进入正常的发现与预览路径。

这是文件发现范围的设计限制，并非磁盘未写入。对于长任务中的阶段产物，成功写入与用户可见之间存在缺口；此记录不把未显示的文件说成已可预览。

另外，Pi 随后在正文输出了粗体的绝对路径，仍未被识别。针对项目实际 `extractLocalPaths` 的非模拟诊断证实：同一个路径写成普通文本、行内代码或 Markdown 链接都能提取，粗体 `**路径**` 返回空数组。`local-paths.ts` 只清理列表/标签/成对引号等，没有处理加粗包装。实际函数输出保存在 `path-extraction-diagnostic.json`，诊断脚本没有修改业务函数。

## 6. 长会话完成后，完整刷新触发 Electron contextBridge 递归深度错误（高优先级）

在48个实验、阅读包和Paper2Any测试完成的长会话中，右上角出现 `Uncaught TypeError: Electron contextBridge recursion depth exceeded. Nested objects deeper than 1000 are not supported.`。再次按Enter提交补充任务，Pi确实接收并继续执行，但提示“Pi已接收输入，但刷新失败”。保存现场截图09。不能把这一长任务稳定性视为通过。

只读诊断从真实JSONL恢复到359个会话树节点的祖先链，没有缺失父节点。`src/main/index.ts:904` 的 `mapTreeNode` 将每个节点的children递归保留；hydrate在1031附近把全树返回给renderer；`src/preload/index.ts:101` 的refresh直接把完整bootstrap跨contextBridge。这些事实与桥接深层嵌套错误一致，尚未插桩锁定具体过桥对象及Electron内部计数方式，因此不把359个节点简单说成359层或精确1000层JavaScript嵌套。没有为通过测试而截断/丢弃会话树。

影响范围与状态：流式工具执行及磁盘文件仍正常，完整状态刷新失败。科学结果独立校验通过并不等于GUI稳定性通过。此次保持业务代码不变，缺陷未修复。

## 7. PDF图像可见，内置阅读器文本提取有警告

右栏实际打开65页作者稿，正文、缩略图、页数和缩放可见。可访问性树同时报告“无法访问此PDF文件。无法下载文本提取文件，请稍后再试。”。因此只能确认视觉预览可用，不能把辅助技术文本读取判为通过。截图07保留视觉现场。

## 8. PPTX 默认缩放未适应窄右栏

实际打开最终16页PPTX，右栏约720px宽，100%时第2页表格最右列被裁切；缩小到70%才显示完整页面。表格内容和第7页原生柱状图均能显示，下一页和页码下拉有效。缩放同时影响内嵌页码控件，70%时控件也变小。这是预览可用性限制，不是PPTX文件损坏；独立重导入的16页渲染均已由当前主代理逐页检查。

关闭右侧检查器后聊天区域扩展，重新打开仍保留第7页和70%缩放，恢复行为通过。截图08保存了实际图表预览。没有把此有限范围验证声称为PowerPoint原生应用或像素级兼容性验收。

## 验收界限

上述缺陷不影响已经落盘的科学预测文件，但影响状态可见性和交互预期。未把自动压缩、所有模型、macOS、完整 Paper2MCP 或 Paper2Any 图像生成流程标为通过。测试过程中最初的401来自测试配置生成器使用了旧环境变量语法，与用户原有密钥是否有效无关。
